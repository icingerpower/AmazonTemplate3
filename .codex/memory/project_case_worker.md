Feature: semi-automated Amazon Seller Support **case** replies. No SP-API exists for support cases (Messaging API only covers fixed order-scoped buyer messages), so we drive the Seller Central UI with Playwright.

**Design decisions (from user):**
- Draft-first / human-in-the-loop by default.
- Playwright lives in a **separate Node worker** (not in the Qt app). **ARCHITECTURE CHANGED: no persistent server/TCP.** The app launches the worker **one-shot per phase via QProcess** (like the AI CLIs) — feed JSON job on stdin, read one JSON result on stdout, process exits. No port, no "is the server running", click-and-go. Entry: `case-worker/src/oneshot.ts` (actions: scrape/reply/login). App finds it via `CASE_WORKER_DIR` compile define (=`${CMAKE_SOURCE_DIR}/case-worker`), overridable by QSetting `cases/workerDir`. Qt side = `CaseWorkerRunner` (QProcess) — **replaced** the old `CaseWorkerClient` (TCP, deleted). `server.ts` kept only for manual debugging.
- Login pause is in the WORKER, not Qt: `oneshot.ts` `ensureLoggedIn()` runs once per region BEFORE any case, navigates to the lobby, and if signed out **blocks polling every 2s up to ~10min until the user logs in** in that same window. (Earlier Qt-side after-the-fact login dialog removed — it flipped through case pages without pausing.)
- **Login detection is URL-based, NOT DOM selectors** (`isLoggedIn` in casePage.ts): signed-out → Amazon auth URL (`/ap/signin|cvf|mfa|register|authportal`); signed-in → any `sellercentral.<tld>/` non-auth page. Robust vs. untuned selectors.
- **Correct URLs (config.example.json)**: EU domain = `sellercentral.amazon.co.uk` (NOT .fr); case url = `https://{domain}/cu/case-dashboard/view-case?ref=sc_cd_lobby_vc_v3&ie=UTF&caseID={caseId}`; lobby = `https://{domain}/cu/case-lobby`. NA=.com, JP=.co.jp.
- **Account-switcher**: after login Amazon shows a "Select an account" marketplace page (`/account-switcher/…merchantMarketplace?returnTo=…`). `casePage.ts passAccountSwitcher()` clicks the target country row + "Select account". The target marketplace is a **per-group setting** chosen in a NEW `comboBoxAccount` (empty default) in PaneCases — `CaseGroup.account` (group.ini `group/account`), threaded per-case: `WorkerCase{region,caseId,account}` / `ReplyJob.account` → oneshot job → `getThread/fillReply(...,account)`. **Run is BLOCKED until a marketplace is picked** (buttonRunSelected disabled when account empty; _runTargets warns listing groups missing it). comboBoxAccount repopulates from region (accountsForRegion: eu=UK/DE/FR/…, na=US/CA/MX/BR, jp=Japan); choice reset when region changes. Config `regions.*.accountCountry` is a fallback only.
- **Drafting uses `AbstractCli` (common/aicli), NOT OpenAi2.** CLI chosen in a QComboBox exactly like PaneWarnings (`setAvailableClis`, remember in QSettings `cases/selectedCli`, draft via `cli->runPromptAsync(prompt, workDir, ctx, cb)` — never co_await runPrompt, see [[project-cli-runprompt-crash]]).
- **Group** = handles one or several cases, has its own subfolder = the CLI `workingDir`. Instructions live **per group** (not per case). Groups created **manually** in PaneCases.
- **autoSend + matchHint are DROPPED** — the post-run review dialog (checkboxes) is the human gate, so no per-group autoSend flag and no keyword auto-suggest.
- **Region-scoped**: Seller Central sessions are per-region (eu/na/jp), matching the app's EU/NA/JP refresh-token split — an EU case only exists on the EU dashboard. Worker has one Chromium profile + login **per region** (`npm run login -- <eu|na|jp>`); every RPC/CLI call takes a `region` param. Config `regions{eu,na,jp}.{domain,userDataDir,locale}` + `defaultRegion`.

**PaneCases.ui (designed by user) + agreed behaviour:**
- Toolbar: `comboBoxCli` (CLI pick, persist like PaneWarnings), `buttonAddGroup`, `buttonAddCase`, `buttonMarkCaseDone` (toggle done on selected case), spacer, `buttonRunAll` (run all not-done cases in all groups).
- `treeViewCases`: groups (parents) → cases (children). Needs columns: case id / subject / done-state.
- Right detail panel (for selected group): `comboBoxCasesUrl` = region **case-lobby URL** picker (entries carry eu/na/jp as data → sets group region); `buttonCopyUrl` copies it; `buttonOpenFolder` opens the group folder (QDesktopServices) so user drops in images/docs; `buttonRunSelected` ("Run") runs selected group/case; `textEditPrompt` = the group's instructions (load/save group.ini).
- **CRITICAL invariant**: the folder `buttonOpenFolder` opens == the `workingDir` passed to `cli->runPromptAsync(prompt, workingDir, …)`. One path per group: `{workingDir}/cases/{group}/` (holds group.ini, CLAUDE.md, images/docs the user drops, threads/{caseId}.json). A single `_groupDir(group)` helper must be the sole source of this path for both the button and the CLI run.
- **Run flow**: for each case → worker.getThread(region,caseId) → prompt = group instructions + thread (+ images in group dir) → `cli->runPromptAsync(prompt, groupDir, …)` → collect draft.
- **Review dialog** (opens after Run/RunAll): row per case = Amazon last reply + CLI draft + checkbox (default checked); can **re-run one case with an extra prompt msg**; **Validate** → for each checked case worker.fillReply(region,caseId,draft) then worker.send, then mark done.
- Folder layout under workingDir:
  `cases/{group}/group.ini` (case IDs, instructions, autoSend, matchHint),
  `cases/{group}/CLAUDE.md` (per-group CLI memory, persists across replies),
  `cases/{group}/images/` (attachments the CLI reads — it runs in this dir),
  `cases/{group}/threads/{caseId}.json` (scraped thread from Node worker).

**Built so far:** `case-worker/` standalone Node/TS project (Node 24, Playwright, tsx). Persistent Chromium context (login once w/ MFA, reuse session). Ops: `getThread` / `fillReply` (types, never sends) / `send` (separate call) / `ping`. TCP JSON-lines server on 127.0.0.1:8787 (`src/server.ts`), serialises all browser work through one context. CLI harness `src/cli.ts` (login/open/thread/fill/send). Selectors centralised in `config.json` (gitignored; copy from config.example.json) — they are GUESSES needing tuning against live DOM.

**DONE (Qt side):** `CaseGroup` (Lib) loads/saves group.ini + folder/CLAUDE.md/threads; `CaseWorkerRunner` (Lib, QProcess one-shot); `PaneCases` fully wired — CLI combo (persist `cases/selectedCli`), group tree, add group/case (dedup across ALL groups, trims id), mark done, open folder, copy url, region via comboBoxCasesUrl, prompt load/save; run flow = batch scrape → skip non-amazon-turn → draft eligible via CLI (workingDir=group dir) → stopgap `_openReview` QMessageBox. Reuses shared [[project-discount-feature]] `makeProgressDlg`.

**Selectors TUNED (config.example.json) from real DOM dump** (getThread writes `screenshots/thread-{region}-{caseId}.html` for debugging). Class names are RANDOMIZED (CSS modules) — anchor on data-test-tag/data-testid only: message=`[data-test-tag='inline-contact']`, author=`[data-testid='sender-label']` (values "Amazon"/"You"), body=`[data-test-tag='contact-full'], [data-test-tag='contact-preview']` (full=expanded, preview=collapsed), time=`xpath=.//div[@data-testid='sender-label']/../following-sibling::div[1]`, subject=`[data-test-tag='case-title']`, status=`[data-test-tag='case-status']`. Reply editor/send-button selectors still UNVERIFIED (need to click Reply and dump). **DOM is NEWEST-FIRST** → getThread does `messages.reverse()` so chronological (oldest→newest); critical for isAmazonTurn/lastAmazonReply.

**Review + send DONE**: `DialogReviewReplies` (gui/panes) — per-case cards: Amazon last reply (read-only) + editable draft + checkbox (default checked) + attachment note; top checkbox **"Let me click Send myself"** (unchecked=auto-send) → `letUserSend()`. `_openReview`→dialog→`_sendReplies(approved, manualSend)`→`m_runner->reply(jobs, manualSend, …)`. **Cases are NEVER auto-marked done** (user's rule: Amazon usually replies again, so keep replying). After we send, the case's last msg is ours → auto-skipped as "waiting for Amazon" next run; re-drafts when Amazon replies again. Only the USER marks done (Mark/Unmark button).
**Attachments**: files dropped **directly in the group folder** `{workingDir}/cases/{group}/` (the "Open folder" target). `CaseGroup::attachmentFiles()` lists root files EXCLUDING group.ini + CLAUDE.md (subdirs like threads/ auto-skipped). → CaseDraft.attachments → ReplyJob.files → worker `submitReply()`: openCase→click Reply→fill→`setInputFiles`→**if attach fails, does NOT click Send** (returns error, sent=false). manualSend: fill+attach then poll ~5min for user to click Send (editor disappears=sent). submitReply dumps `screenshots/reply-{region}-{caseId}.html`.
**TEMPORARY**: `_collectTargets` capped to FIRST not-done case per group (`kFirstCasePerGroupOnly=true` in PaneCases.cpp) — remove to process all.

**Reply-editor selectors TUNED from dump** — it's a Katal form (web components, inner input/textarea in SHADOW DOM → NOT in page.content() dumps; Playwright pierces open shadow DOM at runtime). Hooks: message box `[data-test-tag='textarea-describeIssue'] textarea`, uploader `kat-file-upload input[type='file']` (has `multiple`, max 6 files/10MB), send `#reply-email-button`, replyButton `kat-button[label='Reply']`. Earlier bug: old `"textarea"` selector matched a HIDDEN exit-survey textarea first → bailed before attaching. `submitReply` now logs step counts to stderr (replyButton/textarea/attachInput/sendButton counts, typed chars, setInputFiles ok) → streamed to app progress log; use these to debug since shadow DOM isn't in dumps.

**WORKING end-to-end** (scrape → draft → review → attach → send confirmed). First-case-per-group test cap REMOVED — `_collectTargets` now processes all not-done cases. Robustness: `launchContext` retries 6×/2s on profile-lock; oneshot wraps region work + login in try/finally so `ctx.close()` always runs (prevents leftover Chrome locking the next run). **Amazon closes the case tab after a reply is submitted** → oneshot grabs a LIVE page per case (`ctx.pages().find(!isClosed) ?? ctx.newPage()`); same persistent context = still logged in. If the browser is closed entirely, it stops gracefully (no per-case error spam).

**Risk note:** automating Seller Central is gray-area per Amazon ToS; draft-first keeps account-suspension risk low. Run headed.
