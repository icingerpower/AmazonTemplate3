Temu EU local-seller API (gateway `https://openapi-b-eu.temu.com/openapi/router`, POST JSON). Verified live 2026-07 with the Icinger FR store. Implemented in `AmazonTemplate3Lib/apis/TemuInventoryApi.{h,cpp}`.

**Marketplace order display (2026-09-16, corrected scope):** `PaneMarketplaces` bottom table adds only Order Date alongside the existing fulfillment/order IDs, tracking, and store. The user's clarification supersedes the initial addition of SKU, quantity, and status columns; those extra columns were removed. `TemuInventoryApi::fetchUnshippedOrders` reads `pageItems[].parentOrderMap.parentOrderTime`, falling back to `orderList[].orderCreateTime`; positive epoch seconds become a UTC `QDateTime` carried through `MarketOrder`. The table displays local time (`yyyy-MM-dd HH:mm`); missing timestamps stay blank. Schema checked against the [official order-list reference](https://partner.temu.com/documentation?sub_menu_code=554fd46b45ee49269cbdd6d4008a5dc1); no live order API calls made for this display change. Existing pending-orders/30-day scope remains.

**Signing:** MD5(appSecret + concat(sortedKey+value) + appSecret), uppercase hex. Ints without decimals, bools as "true"/"false", arrays/objects as compact JSON. Common params: `type`, `app_key`, `access_token`, `data_type:"JSON"`, `version`, `timestamp` (secs), `sign`. IP whitelist enforced — calls must come from the machine's whitelisted public IP (which is also Claude Code's machine, so probing with python from a script works; see scratchpad temu_probe*.py pattern).

**Error codes:** 3000003 = "type not exists" (wrong endpoint name). 7000000 BUSINESS_SERVICE_ERROR = endpoint EXISTS but params wrong (usually a missing required param, NOT pagination). 3000000 = param type error (e.g. string where int expected) — these messages are informative, use them to discover schemas.

**Working endpoints:**
- `bg.local.goods.list.query` V1 — REQUIRES `goodsSearchType` as INT (1=active, 6=other visible status; other values → result null). Params: `pageNo`, `pageSize` (50 ok), optional `goodsIdList` filter. Response: `result.goodsList[]` with `goodsId`, `outGoodsSn`, `outSkuSnList` (seller SKUs), `skuIdList`, goods-level `quantity` (stock), prices. `skuInfoList` always empty.
- `bg.local.goods.detail.query` V1 — param `goodsId`. Returns `skuList[]` with `outSkuSn`, `skuId`, prices, weights — but NO stock.
- `bg.order.list.v2.get` V2 — params `pageNo/pageSize`, `createAfter/createBefore` (epoch secs). Response `result.pageItems[].orderList[].productList[]` with `extCode` (seller SKU), `productId`, `productSkuId`, `quantity`. Used for sales counting.
- `bg.local.goods.stock.edit` V1 — DIFF-based stock update, verified live: `{goodsId, skuStockChangeList: [{skuId, stockDiff}]}` where stockDiff = target − current (skuId from goods list `skuIdList`). CAUTION: `success:true` is NOT enough — check `result.operateResult` and `skuStockEditStatusInfoList[].stockEditStatus` (stockDiff=0 returns success:true but operateResult:false). Absolute params (`quantity`, `targetStockAvailable`) → 150010003 Invalid Request Parameters. Decrements propagate slowly (~10s before list.query reflects them).
- `bg.logistics.companies.get` V1 — REQUIRES int `regionId`. Returns `result: [{logisticsServiceProviderId, logisticsServiceProviderName, logisticsBrandName}]`. Carrier IDs are globally consistent across regions; lists differ per region (rich EU regions: 13, 20, 32, 69, 76, 90, 98). Amazon MCF carriers: `swiship(FR)`=998264966, `Amazon shiping(FR)`=998264967, `swiship(DE)`=998264957 (regions 69/76/90/96/98). `bg.shiporder.logistics.get` does NOT exist (3000003).
- `bg.logistics.shipment.v2.confirm` V1 — schema verified by wrong-type probing (2026-07-04): `{sendType: 0, sendRequestList: [{carrierId, trackingNumber, orderSendInfoList: [{parentOrderSn, orderSn, goodsId, skuId, quantity}]}]}`. `goodsId`/`skuId` MUST be the ORDER-level ids from `bg.order.list.v2.get` `orderList[].goodsId/skuId` — using `productList[].productId/productSkuId` gives 20006 "The order and Order item ID do not match". Amazon "Amazon Logistics" maps to Temu `swiship(CC)`. `bg.logistics.shipment.confirm` and `.get` (non-v2) return 3000037 "migrate to higher version".

**Param discovery trick:** unknown fields are silently ignored (generic 7000000); KNOWN fields with a wrong type return informative errors — `3000000 "X type error"` for ints/objects/lists, `4000006` for strings fed a list. Probe one field at a time with a deliberately wrong type to map any endpoint's schema without side effects (use fake orderSn values so nothing real is mutated).

- `bg.order.shippinginfo.v2.get` V1 — param `parentOrderSn`; returns full consignee address: `receiptName`, `addressLine1/2`, `regionName1` (country) / `regionName2` (region) / `regionName3` (city), `postCode`, `mobile`, `mail` (relay email). Verified live 2026-07-04 for local EU sellers. `bg.order.detail.v2.get` also exists.

**Per-SKU stock (SOLVED 2026-07-03):** `bg.local.goods.sku.list.query` V1 requires `skuSearchType` as INT: 2 = in-stock SKUs, 3 = out-of-stock SKUs — both return `skuList[]` with `skuSn` (seller SKU), `skuId`, `goodsId` and REAL per-SKU `stock`. Type 7 lists all SKUs but stock is always 0 (unusable) and its pagination repeats pages (cap page loops!). The goods-level `quantity` from goods.list.query DISAGREES with per-SKU stock for multi-SKU goods — always use the SKU-level endpoint. Types 0/1/4/5/6/8/9/10 return empty/null.

**Product create/update (MAPPED 2026-07-05, not yet built):**
- **Update detection:** `temu.local.goods.list.retrieve` V1 (goodsSearchType string: ALL/ACTIVE/INACTIVE/INCOMPLETE/DRAFT/DELETED) with `outSkuSnList=[sku]` → `result.goodsList[]{goodsId, catId, outGoodsSn, skuInfoList[]{skuId, skuSn, specList[]{specId,parentSpecId,parentSpecName,specName}}}`. Found → update; not found → create.
- **USE V3 TO CREATE, NOT V1 (2026-07):** the correct publish endpoint is **`temu.local.goods.v3.add`** (version V3). It is far simpler and avoids every V1 headache: pass **image URLs directly** in `goodsBasic.goodsCarouselImage[]` / `skuList[].images[]` (Temu downloads them — no image.upload/CDN step); give the category by NAME via `goodsBasic.extCatName` (e.g. "Office Products / Office & School Supplies / Book Covers" — no catId/cats.get/spec.id.get); attributes are free `attributes:[{name, value:[...]}]` (no pid/templatePid/vid, no template.get); variations per SKU are `variations:[{name,value}]` (no specId generation, no goodsProperties linkage). Price is `skuList[].price:{basePrice:{amount,currency}, listPrice:{amount,currency}}` with amount in MAJOR units at the site precision — **France/EUR = 2 decimals** ("12.99"), range [0.01, …]. Packaging `skuList[].packageInfo:{weight,length,width,height}` as numeric strings, EU 1 decimal (g/cm), 0 → Temu default. Required: externalGoodsId, goodsName, externalSkuId, images, basePrice. Returns `{goodsId, externalGoodsId}`; then wait ~10 min and query status via bg.local.goods.list.query / temu.local.goods.list.retrieve (Draft = missing required attrs; Incomplete = submitted for review). The V1 `bg.local.goods.add` price format ("Incorrect price unit" 150010029) was a dead end — existing products were made via V3. Site precision doc: search "site currency" → "Product Differences in site currency, volume".
- **Create (V1, legacy — avoid):** `bg.local.goods.add` V1. Required objects: `goodsBasic`, `goodsServicePromise`, `goodsProperty`, `skuList[]`. `goodsBasic` first-required = `catId` then `goodsName` (150011019 if null); other fields: `hdThumbUrl`, `carouselImageList[]`, `goodsDesc`, `outGoodsSn`, `specIdList`. Optional top-level: `bulletPoints[]`, `goodsDesc`, `goodsSizeChartList`, `goodsSizeImage[]`, `goodsTrademark`, `taxCodeInfo`, `goodsOriginInfo`, `certificationInfo`, `guideFileInfo`. After the obvious fields it returns generic 150010003 (holistic validation) — mirror an existing goods' `bg.local.goods.detail.query` shape rather than blind-probe.
- **Update:** `bg.local.goods.update` V1 EXISTS, requires `goodsId` + changed fields (same object shapes). `.edit/.modify` do NOT exist.
- **goods.add required fields (probed 2026-07, cat 1462):** each SKU needs `quantity` (stock; without it → generic 150010003), `specIdList` (1-2 spec ids from `bg.local.goods.spec.id.get(catId,parentSpecId,childSpecName)`), and **each specId must ALSO appear in `goodsProperty.goodsProperties`** (else "System error"). `goodsServicePromise.costTemplateId` required (freight template, per-store). Packaging: `weight/length/width/height` are **top-level SKU String fields** (e.g. "120.0"), NOT nested productExpressInfo (vol: ≤3 int digits +1 decimal; weight: ≤4 int +1 decimal). If a brand attribute (name=brand, refPid=1960) is in goodsProperties, `goodsTrademark` MUST be included. `importDesignation` must be exact-case from a fixed list. Attribute `templatePid` must match the template.get value exactly. Docs: partner-eu.temu.com "Common Issues During Product Publishing" + "Guide of price" are fetchable via `/riemann/api/v2/menu/document/detail` `{menu_code}` (get menu_code from `/menu/search`).
- **PRICE BLOCKER IS (MOSTLY) A STALE TOKEN (2026-07):** After enabling "Local Price Management" in Seller Center the OLD access token stays valid but WITHOUT the new price rights — must re-authorize/regenerate the token. Diagnostic: `bg.local.goods.priceorder.query` succeeds but `bg.local.goods.sku.list.price.query` → `3000032 access_token don't have this api access, please ask for seller to authorize this api in seller center`. The `150010029 Incorrect price unit` on goods.add is likely the same missing price authorization. FIX: seller re-authorizes the app (new refresh/access token) in Seller Center → update it in the app Settings, then retry. If it persists after a fresh token, THEN it's the whitelist Price-API issue below.
- **PRICE IS A SEPARATE, WHITELIST-ONLY FLOW (2026-07 BLOCKER):** goods.add rejects any directly-supplied price with `150010029 Incorrect price unit` (happens even with NO price once other fields are valid). Per the "Guide of price" doc, for new products you must first call `temu.local.goods.baseprice.recommend` (converts your selling price → Temu base price keeping the same settlement), then pass THAT base price into goods.add. The Price API (`temu.local.goods.baseprice.recommend`, `temu.local.goods.recommendedprice.query`, `bg.local.goods.priceorder.change.sku.price`, `bg.local.goods.priceorder.query`) is a **sensitive interface, only for whitelisted locally-developed apps** — must apply at store level via Temu business team. Our app appears NOT whitelisted: baseprice.recommend returns `3000000 不能为null` (cannot be null) for all inputs incl. unknown field names. Until whitelisted, API product creation is blocked at the price step. netContent unit codes (temu.local.goods.sku.net.content.unit.query): g=5,kg=6,ml=2,l=4,cm=12,count=20 — adding netContent did NOT clear 150010029.
- **SKU price format (probed 2026-07 on goods.add):** `skuList[].retailPrice` = object `{amount:"999" (minor units string), currency:"EUR"}`; but `skuList[].listPrice` = a **plain minor-units number** (e.g. `1599`), NOT an object — an object listPrice returns `3000000 skuList[0].listPrice type error`. (detail.query RETURNS both as objects, but goods.add INPUT wants listPrice as a number.) retailPrice=base/selling, listPrice=higher reference. After fixing price types, minimal payloads still return generic `150010003` until stock/spec fields are supplied.
- **Reference shape** (`bg.local.goods.detail.query` goodsId): top keys skuList, goodsServicePromise, goodsOriginInfo, outGoodsSn, catId, catName, bulletPoints[], goodsName, productType, goodsDesc, goodsSizeChartList, goodsSizeImage, itemTaxCode, goodsProperties[], goodsGallery{detailVideo,goodsCarouselImage,carouselVideo,detailImage}, goodsTrademark{brandName,brandId,trademarkId,trademarkName}. skuList[] item: images[], productExpressInfo{weightInfo{unit,weight}, volumeInfo{unit,width,length,height}}, specIdList[], specNameList[], outSkuSn, retailPrice{amount,currency}, listPrice{...}, skuId. **Prices in MINOR units**: amount "1731" = €17.31. goodsServicePromise{shipmentLimitDay, costTemplateId, costTemplateName, fulfillmentType}.
