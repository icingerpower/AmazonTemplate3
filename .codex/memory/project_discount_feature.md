Discount feature (PaneDiscount, added 2026-07) — aged-FBA-stock discounting for Amazon EU.

Key API facts (hard constraints):
- **Amazon SP-API has NO coupon / deal / Lightning-Deal / promotion creation API.** The only programmatic "promotion" is a scheduled *sale price* (strike-through): PATCH `purchasable_offer` with a `discounted_price` array carrying `value_with_tax` + `start_at`/`end_at` (ISO-8601 UTC), alongside the kept `our_price`. Implemented as `AmazonPricingApi::patchListingDiscount(...)`. The discount price MUST be in the listing's original currency.
- **Inventory age is not in the FBA Inventory API.** It comes only from the `GET_FBA_INVENTORY_PLANNING_DATA` report (FBA Manage Inventory Health), columns `inv-age-*`, `days-of-supply`, `sales-shipped-last-90-days`. Implemented as `AmazonInventoryApi::fetchInventoryAgeReport(...)`, built on the extracted `_runReport()` helper (create→poll→download→gunzip).
- **Currency rates are a shared QSettings store**: `TableCurrencyRates` loads/saves `pricing/rates/{marketplaceId}/rate` (EUR→currency). PaneDiscount reuses these (no CLI of its own); EUR = origAmount / rate. Rates only refresh when the user visits the Pricing tab.

Age-bucket double-count bug (FIXED 2026-07-12): GET_FBA_INVENTORY_PLANNING_DATA carries TWO overlapping inv-age column sets — canonical coarse (inv-age-0-to-90, 91-to-180, 181-to-270, 271-to-365, 366-to-455, 456-plus) AND a fine/alternate set (0-to-30, 31-to-60, 61-to-90, 181-to-330, 331-to-365). Summing every inv-age-* column double-counted (aged > available). Fix: parse ONLY the coarse columns by name (age365plus = 366-455 + 456-plus + legacy 365-plus); regex fallback only when the coarse set is absent. Note: "aged" is on-hand-based (bucket sum) while "available" is fulfillable, so aged can legitimately exceed available when units are reserved/unsellable — logged as info, not an error. PaneDiscount has a persisted "100% aged only" checkbox (default on, QSettings discount/only100Aged) = include only when aged >= totalBucketUnits(). Parent columns show Units(available)/Aged/Sales90 (Sales90 via fetchSalesUnits across checked marketplaces). Temporary load cap: kMaxLoadCandidates in PaneDiscount.cpp (0 = all).

Region support (added 2026-07-12): PaneDiscount has a `comboRegion` (Europe / North America, persisted discount/region). Each region (RegionDef in PaneDiscount.cpp) has its own marketplace list, home marketplace (report + product type), preferred/fallback title marketplaces, and EU-vs-NA LWA token/seller. `AmazonInventoryApi` was made multi-region: `endpointForMarketplace(marketplaceId)` (EU/NA/FE) replaced the hardcoded kEuEndpoint; construct it with the region's marketplace + token/seller and it hits the right host (constructor signature unchanged, so PanePricing/AmazonFbaInventorySource still work with DE→EU). Pools are region-separate so each region loads independently. Fixed US marketplace-ID typo in TableCurrencyRates (ATVPDKIKX0ER → ATVPDKIKX0DER). Note: the "Unit price (EUR)"/"EUR" column stays EUR-normalized even for NA (cross-region comparison); orig amount/currency show the local USD/CAD/MXN.

Design decisions: FBA EU is one pooled inventory, so the tree's per-country "Units" repeats the shared pool figure (parent shows it once). Parent title = preferred language (FR→EN/UK fallback→report product-name); child titles = per-country localized via `AmazonCatalogApi::fetchListingText`. Filters (min months stored / min days of supply / exclude if 90d sales ≥ N) are *inclusion* filters; every included row is "eligible" and its New price cell renders dark red. See [[project_fba_data.md]], [[project_variation_fix_lessons.md]].

Reusable: progress dialog extracted to `gui/panes/ProgressDialog.{h,cpp}` (`makeProgressDlg` / `ProgressDlgHandles`), shared by PanePricing + PaneDiscount.

Marketplace-ID typos (FIXED 2026-07-10): `TableCurrencyRates` and `AmazonFbaInventorySource` had WRONG ids for NL (`A1805IZSGTT6HW` → correct `A1805IZSGTT6HS`) and BE (`ARBP9OOSHTCHU` → correct `AMEN7PMS3EDWL`). Canonical source of truth is `AmazonMarketplace::all()` (AmazonTemplate3/AmazonMarketplace.cpp) — always cross-check IDs there. The typos made per-country price/inventory lookups hit a bogus marketplace → HTTP 404 → shown as "not listed / 0". PaneDiscount's `kEuMarketplaceIds` also corrected.

Min/max price on discount PATCH: `minimum_seller_allowed_price` and `maximum_seller_allowed_price` are sub-fields of `purchasable_offer` (schedule → value_with_tax), readable via the same Listings API call and settable via PATCH. Because our discount PATCH uses `op:replace` on the whole `purchasable_offer`, any omitted sub-field is DROPPED. Per user's choice (2026-07-11), the discount PATCH erases BOTH min and max. IMPORTANT — how to remove them: `purchasable_offer` is one of only TWO attributes that support the `merge` op, and **omitting a sub-field in an `op:replace` does NOT delete it (Amazon keeps the old value)** — verified empirically (min/max still present 6h after a replace-omit). The correct removal is `op:merge` with the sub-field set to explicit `null` (same pattern Amazon documents for un-associating automated_pricing_merchandising_rule_plan). `patchListingDiscount` now uses `op:merge` with our_price + discounted_price + `minimum_seller_allowed_price:null` + `maximum_seller_allowed_price:null`. Also note constraint: "base price must be between min and max or Amazon errors." Diagnostic dump written to `/tmp/sp-api-discount-{sku}-{mp}-{ts}.txt` (request+response) on every discount PATCH. Confirmed 2026-07-11: merge+null PATCH returns status ACCEPTED (async) — removal now goes through (the old replace-omit did not). Product type is PER-MARKETPLACE: reusing DE's `THERAPEUTIC_THERMAL_COMPRESS` made BE (fr_BE) return INVALID code 4000003 "product type invalid/not supported". Fix: `fetchListingPrice` returns productTypeOut per marketplace; PaneDiscount stores it on each CountryRow and passes c.productType (not the DE one) to patchListingDiscount. `fetchListingPrice` returns min+max via out-params so the pane can flag it. TreeSkuDiscount has a read-only **ColEraseMinMax indicator checkbox** (dark-red bg when ticked) = `eligible && (min>0 || max>0)`, so the user can watch these floors/ceilings disappear across reloads.

Price-source limitation (why a *correctly-identified* marketplace can still show blank): `AmazonPricingApi::fetchListingPrice` reads the price from the **Listings Items API** per marketplace (offers → purchasable_offer → list_price). It only sees a price the seller **explicitly set on that marketplace**. Two gaps: (1) HTTP 404 = no per-marketplace listing record → exists=false; (2) HTTP 200 but no price field = price managed by Amazon **Build International Listings (BIL)** → returns the -1.0 sentinel (this is the real PL case). The buyable price shown in Seller Central for those is the BIL-computed price, only available via the **Product Pricing API** (`getPricing`/`getItemOffers`) — a separate SP-API role (adding it requires refresh-token re-auth, see [[project_spapi_auth]]). BIL-managed marketplaces can't be discounted via a purchasable_offer PATCH anyway, so PaneDiscount leaves them blank + `eligible=false` (never PATCHed). TreeSkuDiscount shows blank (not 0/-1) with a tooltip distinguishing "not listed" from "BIL-managed".
